# Термины продукта

## Магазин

Отдельный бизнес или бренд продавца внутри платформы. Магазин принадлежит владельцу, может иметь участников, налоговую ставку и публичную витрину.

Один магазин может одновременно содержать данные Wildberries и Ozon.

## Маркетплейс

Источник финансовых данных внутри магазина: `wildberries` или `ozon`. Каждый отчёт, период, товарная продажа и запись журнала относятся к одной площадке. Справочник себестоимости общий для обеих площадок внутри магазина.

Переключатель в обзоре выбирает данные текущего магазина: только Wildberries, только Ozon или сумму обеих площадок.

Карточка «Заказы» удалена по запросу пользователя из кабинета и публичной витрины для всех площадок. Сумма заказов остаётся в данных для расчёта ДРР и динамики; импорт и API не изменены. Отчёт по начислениям Ozon не устанавливает все оформленные заказы, поэтому продажи не подменяют этот показатель.

При смене площадки, источника WB или периода старые показатели и графики сбрасываются до первого запроса: карточки показывают прочерки и общий индикатор загрузки. Данные появляются после готовности всех блоков; запоздавший ответ не меняет состояние нового выбора. Локальная загрузка обзора не заменяет независимый статус фоновой синхронизации WB.

## Отчёт

Загруженный пользователем файл площадки. Отчёт всегда записывается в текущий магазин и в явно выбранный маркетплейс.

## Диапазон месяцев в обзоре

Режим «Месяц» сохраняет существующие расчёты и редактирование. Режим «Диапазон» суммирует календарные месяцы включительно: KPI, расходы и товары; график показывает только выбранные месяцы. Сравнение — непосредственно предшествующий диапазон такой же длины, только при полной сопоставимой истории. При включении текущего неполного месяца сравнение скрыто.

ДРР и рентабельность считаются из общих сумм, не средним месячных процентов. Артикулы объединяются без учёта регистра внутри площадки, WB и Ozon остаются раздельными; ABC пересчитывается для выбранного диапазона. Неизвестные суммы API остаются неизвестными. Недостающий полный месяц блокирует итог с понятным сообщением, а не подменяется нулём. Источник WB прежний, Ozon — только файлы; режим «Все вместе» требует покрытия обеих площадок.

Редактирование расходов, ИИ-анализ и кнопка API-обновления остаются помесячными. Диапазон только читает сохранённые данные и не запускает синхронизацию WB. Файловые месяцы читаются пакетно с единственным справочником себестоимости; API использует существующий кэш кабинетов с ограниченной параллельностью. Смена магазина сбрасывает диапазон, запоздавшие ответы не отображаются.

## Ручные расходы

Помесячные расходы конкретного маркетплейса внутри магазина, которых нет в загружаемых отчётах.

- **Операционные расходы**: зарплаты, сервисы, упаковка и другие расходы магазина.
- **Расходы на внешнее продвижение**: блогеры, посевы и реклама вне рекламного кабинета маркетплейса.

Обе категории уменьшают чистую прибыль. В режиме «Все вместе» они суммируются по Wildberries и Ozon.

## Автоматические данные Wildberries

«Сумма продаж» — стоимость выкупленных товаров по цене продавца с согласованной скидкой: `retailPriceWithDisc × quantity` для операций продажи минус возвраты. `retailAmount` («WB реализовал товар») и `forPay` («К перечислению продавцу») не заменяют этот показатель. Финансовые суммы WB сохраняются отдельно; «Итого к перечислению» по-прежнему рассчитывается из `forPay` и удержаний. Ту же стоимость выкупов используют выручка SKU, динамика, ДРР выкупа, рентабельность, процент налога пользователя и ИИ-анализ.

Компактная модель API дополнительно хранит `totals.salesAmount`, `products[].sales_revenue` и `sales_covered_rows` без хранения сырых операций. Нет цены хотя бы у одного выкупа — сумма неизвестна, не равна нулю или выплате. Старые агрегаты не восстанавливаются приближённо и не смешиваются с файлами. `tools/repair-wb-sales.mjs` дополняет их только после точного совпадения курсора, количества операций, прежних финансовых сумм и итогов каждого SKU; меняет исключительно новые поля продаж. Не прошедший проверку месяц остаётся нетронутым и требует обычного явного обновления. До восстановления KPI объясняет необходимость обновления; при ненулевой ставке неизвестны также налог и чистая прибыль. Пустой завершённый отчёт и товары с явной нулевой ценой дают известный ноль. Выплата WB не зависит от доступности цены выкупов.

Публикация исправления требует обеих функций `wb-api` и `analyze-results`, затем клиентских файлов с версией `20261027-sales1`. Это добавочные JSON-поля, без миграции схемы или удаления истории. Обычное чтение кабинета не запускает запросы к WB. Одноразовое восстановление истории требует явного запуска `tools/repair-wb-sales.mjs --apply`; по умолчанию инструмент только показывает план. Оно читает финансовый отчёт, не загружает заново остальные источники и не сохраняет исходные операции. Служебные обращения выполняются последовательно, запросы WB — по независимым лимитам каждого магазина. Изменение покрытия завершённого снимка инвалидирует клиентский кэш, не подменяя дату исходной выгрузки.

Любой владелец магазина может подключить свой персональный ключ WB в настройках. Ключ хранится в Vault и не возвращается в браузер. Участники магазина видят его аналитику, но не могут подключать, заменять, проверять или отключать ключ.

Фоновая очередь загружает текущий и 11 предыдущих месяцев независимо от открытой страницы. Данные API и отчёты из файлов не суммируются для одной площадки: источник WB выбирается в настройках отдельно для каждого магазина. Без подключения сохраняется файловый дашборд. Ozon всегда загружается из ручных отчётов; «Все вместе» складывает выбранный источник WB и файлы Ozon.

Себестоимость общая для площадок внутри магазина. Незаполненная себестоимость и неподтверждённые источники API не считаются нулём. API-данные доступны только владельцу и участникам, не через публичную витрину.

Если в финансовой детализации API есть удержания «WB Медиа», сумма этих удержаний (с учётом возвратов) используется как подтверждённый источник медийных расходов. Ноль из карточек кампаний не отменяет финансовые списания. Статистика кампаний и финансовые удержания не складываются: это пересекающиеся источники с разными датами признания расходов. Прибыль учитывает рекламу один раз; объяснение источника находится в подсказке обзора и в настройках API. Правило применяется ко всем магазинам и к уже сохранённым месяцам, включая динамику, без повторной загрузки финансовых операций.

Решение владельца от 12.10.2026: в API-режиме использовать возвращённые WB суммы, без ручной подстановки названной ранее суммы за сентябрь и без обязательной сверки с выпиской. Текущий приоритет финансового источника WB Медиа сохраняется; это учёт по финансовым удержаниям (`recognition: financial_report`), а не обещание совпадения с календарными затратами кампаний. Отсутствие источника или ошибка API по-прежнему не подменяются нулём.

Сопоставление себестоимости не учитывает регистр букв и пробелы по краям артикула: `Top-114` и `top-114` — один товар. Написание из отчёта сохраняется. При чтении заполненная цена приоритетнее нулевой карточки; среди заполненных выбирается последняя сохранённая. Ручное сохранение, импорт и отмена импорта атомарно обновляют все варианты регистра внутри одного магазина; цены других магазинов не используются.

API, файлы WB и файлы Ozon заводят новые карточки через `seed_cost_cards`: если артикул уже есть в другом регистре, нулевая карточка не создаётся и заполненная цена не меняется. Создание и редактирование используют общую транзакционную блокировку по магазину + нормализованному артикулу. ИИ-анализ использует тот же справочник цен и постранично читает продажи/себестоимость, не обрезая каталог на 1 000 товарах.

## ИИ-анализ

Доступен только владельцу платформы через серверную проверку `is_admin()`, не через редактируемый Telegram-ник. Анализирует выбранный источник WB: API использует тот же `readCabinet` и готовые финансовые агрегаты, что обзор; файлы — загруженные отчёты. Ozon всегда файловый, «Все вместе» не дублирует WB из файлов и API. Неизвестная прибыль и себестоимость API остаются `null`; реклама не вычитается повторно. Текущий неполный API-месяц не сравнивается с полным предыдущим. Кэш зависит от финансовых данных, периода и источника, а не от времени обновления задания; неизменные данные не вызывают новый запрос OpenAI. Запоздавший ответ не отображается после смены магазина, площадки или периода.
