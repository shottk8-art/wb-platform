# Термины продукта

## Магазин

Отдельный бизнес или бренд продавца внутри платформы. Магазин принадлежит владельцу, может иметь участников, налоговую ставку и публичную витрину.

Один магазин может одновременно содержать данные Wildberries и Ozon.

## Маркетплейс

Источник финансовых данных внутри магазина: `wildberries` или `ozon`. Каждый отчёт, период, товарная продажа и запись журнала относятся к одной площадке. Справочник себестоимости общий для обеих площадок внутри магазина.

Переключатель в обзоре выбирает данные текущего магазина: только Wildberries, только Ozon или сумму обеих площадок.

Карточка «Заказы» показывает сумму и количество заказанных единиц товара (не уникальных корзин), с отдельным сравнением каждого показателя с прошлым месяцем. API WB использует уже сохранённые `orders_amount` и `orders_count`; сводный файл — «Сумма заказов…» и «Заказано, шт.». Старые импорты без количества показывают прочерк до повторной загрузки. Отчёт по начислениям Ozon не устанавливает все заказы: карточка Ozon и общий итог с Ozon не подменяют их выкупами/продажами. Клик по карточке включает динамику суммы заказов.

При смене площадки, источника WB или периода старые показатели и графики сбрасываются до первого запроса: карточки показывают прочерки и общий индикатор загрузки. Данные появляются после готовности всех блоков; запоздавший ответ не меняет состояние нового выбора. Локальная загрузка обзора не заменяет независимый статус фоновой синхронизации WB.

## Отчёт

Загруженный пользователем файл площадки. Отчёт всегда записывается в текущий магазин и в явно выбранный маркетплейс.

## Ручные расходы

Помесячные расходы конкретного маркетплейса внутри магазина, которых нет в загружаемых отчётах.

- **Операционные расходы**: зарплаты, сервисы, упаковка и другие расходы магазина.
- **Расходы на внешнее продвижение**: блогеры, посевы и реклама вне рекламного кабинета маркетплейса.

Обе категории уменьшают чистую прибыль. В режиме «Все вместе» они суммируются по Wildberries и Ozon.

## Автоматические данные Wildberries

Любой владелец магазина может подключить свой персональный ключ WB в настройках. Ключ хранится в Vault и не возвращается в браузер. Участники магазина видят его аналитику, но не могут подключать, заменять, проверять или отключать ключ.

Фоновая очередь загружает текущий и 11 предыдущих месяцев независимо от открытой страницы. Данные API и отчёты из файлов не суммируются для одной площадки: источник WB выбирается в настройках отдельно для каждого магазина. Без подключения сохраняется файловый дашборд. Ozon всегда загружается из ручных отчётов; «Все вместе» складывает выбранный источник WB и файлы Ozon.

Себестоимость общая для площадок внутри магазина. Незаполненная себестоимость и неподтверждённые источники API не считаются нулём. API-данные доступны только владельцу и участникам, не через публичную витрину.

Если в финансовой детализации API есть удержания «WB Медиа», сумма этих удержаний (с учётом возвратов) используется как подтверждённый источник медийных расходов. Ноль из карточек кампаний не отменяет финансовые списания. Статистика кампаний и финансовые удержания не складываются: это пересекающиеся источники с разными датами признания расходов. Прибыль учитывает рекламу один раз; объяснение источника находится в подсказке обзора и в настройках API. Правило применяется ко всем магазинам и к уже сохранённым месяцам, включая динамику, без повторной загрузки финансовых операций.

Сопоставление себестоимости не учитывает регистр букв и пробелы по краям артикула: `Top-114` и `top-114` — один товар. Написание из отчёта сохраняется. При чтении заполненная цена приоритетнее нулевой карточки; среди заполненных выбирается последняя сохранённая. Ручное сохранение, импорт и отмена импорта атомарно обновляют все варианты регистра внутри одного магазина; цены других магазинов не используются.

API, файлы WB и файлы Ozon заводят новые карточки через `seed_cost_cards`: если артикул уже есть в другом регистре, нулевая карточка не создаётся и заполненная цена не меняется. Создание и редактирование используют общую транзакционную блокировку по магазину + нормализованному артикулу. ИИ-анализ использует тот же справочник цен и постранично читает продажи/себестоимость, не обрезая каталог на 1 000 товарах.
