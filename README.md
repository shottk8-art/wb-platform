# dvoeplay

Игры для двоих: десять готовых игр и общий главный экран.
В каждой игре есть режим по сети — два телефона соединяются по пятизначному коду
комнаты. Игроки могут назвать себя: имя заменяет «Красные / Жёлтые» и «Соперник»
в табло и в итогах. На главном экране собирается мини-турнир: несколько игр
подряд на одном телефоне и фант проигравшему, который втайне вписал соперник.

## Что где лежит

```
public/                    сайт: главный экран и десять игр
  net.js                   общий модуль сетевой игры — подключают все десять
  tour.js                  общий модуль мини-турнира — подключают все игры и главный экран
  sw.js                    офлайн-режим: после первого открытия игры работают без сети
  manifest.webmanifest     манифест: приложение ставится на телефон без адресной строки
  *.png, favicon.svg       иконки: iPhone, Android, вкладка браузера
  _headers                 заголовки для Netlify (кеш sw.js, тип манифеста)
netlify/functions/
  room.mjs                 единственная серверная функция, отвечает на /api/*
  lib/rooms.mjs            логика комнат — без привязки к Netlify, поэтому её же гоняют тесты
netlify.toml               что публиковать и где искать функции
package.json               одна зависимость: хранилище Netlify Blobs
tools/                     локальный сервер, тесты и сборка иконок, на сайт не попадают
```

Игры лежат по одному файлу каждая, но самодостаточными больше не являются:
рядом должны быть `net.js` и `tour.js`.

## Как это опубликовать

Раньше сайт заливался перетаскиванием архива. Так больше не выйдет: **перетаскивание
папки не поддерживает серверные функции** — Netlify собирает их только из репозитория
или через свою утилиту. Поэтому проект надо один раз связать с GitHub, дальше всё
обновляется само.

### 1. Положить проект на GitHub

Если git установлен:

```bash
cd dvoeplay
git init
git add .
git commit -m "dvoeplay: игры для двоих + игра по сети"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/dvoeplay.git
git push -u origin main
```

Если git ставить не хочется — на github.com нажмите **New repository**, назовите его
`dvoeplay`, создайте, а на странице пустого репозитория выберите
**uploading an existing file** и **перетащите** туда содержимое папки —
именно перетащите: через кнопку «choose your files» структура папок теряется,
и сборка падает с «Deploy directory 'public' does not exist». Лучше из Chrome.

### 2. Связать с проектом на Netlify

Проект `dvoeplay` на Netlify уже есть, пересоздавать его не нужно — адрес
останется прежним.

1. Откройте проект → **Project configuration** → **Developer settings** →
   **Continuous deployment** → раздел **Repository**.
2. **Link repository** → GitHub → выберите `dvoeplay`.
3. Ветка `main`. Команду сборки оставьте пустой, publish directory — `public`,
   functions directory — `netlify/functions`. Всё это уже написано в `netlify.toml`,
   Netlify подставит само.
4. **Deploy**.

Первая сборка поставит `@netlify/blobs` и соберёт функцию. Дальше любой `git push`
публикует новую версию сам.

Хранилище комнат настраивать не нужно: в функциях Netlify Blobs включается сам,
ключи и доступ Netlify подставляет за вас.

### 3. Проверить, что сеть ожила

Откройте любую игру, выберите **По сети** → **Создать комнату**. Если вместо кода
появилось «Сетевая игра на этом адресе не работает» — функция не собралась,
смотрите **Deploys → Functions** в панели Netlify.

## Как приложение

Сайт ставится на телефон как приложение: на iPhone — «Поделиться → На экран
«Домой»», на Android Chrome сам предложит «Установить приложение». Открывается
без адресной строки, со своей иконкой, и после первого открытия работает без
сети (кроме игры по сети). Новая версия, выложенная на сайт, подхватывается со
второго запуска: сначала приложение открывается из кеша, а свежие файлы тихо
скачиваются в фоне.

Внутри Telegram приложение подключает скрипт Telegram, разворачивается на всю
высоту, не даёт свайпом вниз свернуть себя посреди партии, красит шапку в цвет
своей темы, показывает в играх кнопку «Назад» и вибрирует через Taptic.

Если в серии появляется новая страница (новая игра), её надо добавить в список
`FILES` в `sw.js` и поменять там `VERSION` — `tools/audit.py` об этом напомнит.
PNG-иконки в этот список не входят: сервис-воркер пропускает их мимо кеша, чтобы
система всегда получала с сайта свежую иконку.

Все иконки собираются из одной картинки `tools/icon-source.png`:

```bash
python3 tools/icons.py      # нужны numpy, scipy и Pillow
```

Скрипт кладёт в `public/` иконку для iPhone, две для Android и компьютера,
maskable-иконку (рисунок ужат в безопасный круг, фон продлён до краёв) и значок
вкладки — только руки, без надписи. Новая иконка — новый исходник и тот же запуск.

## Мини-турнир

Турнир собирается на главном экране: игры (случайно 3 или 5, либо выбрать
самим в нужном порядке) и фанты — каждый втайне пишет фант сопернику. Кто
играет, турнир не спрашивает: имена берутся из настроек приложения, а без них
стороны зовутся по цветам, как в играх.
Играется вдвоём на одном телефоне; при равенстве дописывается решающая игра.
В конце проигравший открывает фант, который вписал победитель.

Ведёт турнир `public/tour.js`, и сами игры для этого не менялись: игра,
открытая по ссылке `?tour=<номер>`, сразу начинает партию вдвоём, итог узнаётся
из события `dp:save`, которое бросает общий блок памяти после записи партии, а в
шторку итога встаёт панель турнира с кнопкой «Дальше». «Виселица» в турнире
идёт в два раунда — роли в ней неравны, и каждый должен и загадать, и отгадать.
Состояние турнира лежит в общей памяти приложения (`dvoeplay:v1` → `tour`).
Проверяется `tools/test-tour.mjs`.

## Как устроена игра по сети

По сети играются все десять игр. «Доббль» — единственная без очереди: там ходят
оба одновременно, комната заводится с `free:true`, и сервер просто складывает
заявки в общий список в порядке прихода (подробности — в конвенциях серии).
Остальные партии синхронизируются **списком ходов**, а не
картинкой поля: игры детерминированные, поэтому достаточно передать сам ход, а
состояние поля каждый считает у себя. Ход — маленькое значение JSON: номер
столбца, пара «откуда-куда», слово целиком.

Комната живёт в Netlify Blobs и хранит:

| поле      | что это                                         |
|-----------|-------------------------------------------------|
| `seats`   | два токена игроков; `false` — место освобождено  |
| `seen`    | когда каждый последний раз выходил на связь      |
| `round`   | номер раунда, задаёт, кто ходит первым           |
| `moves`   | ходы текущего раунда                             |
| `rematch` | кто уже согласился на реванш                     |
| `turn`    | чья сейчас очередь                               |
| `seed`    | общая случайность на всю комнату                 |
| `who`     | имена, которыми игроки представились             |
| `mids`    | метка последнего принятого хода каждого          |

Очерёдность сервер хранит явно: ходящий сам сообщает, к кому переходит очередь.
Так и должно быть — в «Точках и квадратах», «Мемо-дуэли» и «Захлопни ящик» ход
часто остаётся за тем же игроком. Сходить дважды подряд или за соперника нельзя:
такой запрос получает 409, и клиент пересобирает поле по серверному списку.

**Запись в комнату условная.** Комната — один объект, и оба игрока пишут в неё
разом. Наивное «прочитал — изменил — записал» теряет ходы: пока один читал,
второй успел сходить. Поэтому чтение отдаёт `etag`, а запись проходит, только
если с тех пор комнату никто не трогал; не прошла — действие повторяется с
новым чтением. Опрос состояния вообще ничего не пишет: отметка «на связи»
обновляется не чаще раза в шесть секунд.

**Ход не теряется при обрыве связи.** Клиент держит очередь своих ходов и
повторяет отправку, пока сервер не подтвердит. У каждого хода метка `mid` —
повторно пришедший ход не применяется дважды.

Где в игре есть случайность, влияющая на обоих, она берётся от **зерна комнаты**:
колода в «Мемо-дуэли», загаданное слово в «5 буквах», броски кубиков в «Захлопни
ящик». Поэтому у игроков всё совпадает без лишней пересылки.

Клиент опрашивает сервер по таймеру и разряжает опрос, когда ждать нечего:
0,9 с пока ждём чужой ход, 2,6 с когда ход наш, 4 с если на экран не смотрят,
1,5 с в лобби, 1,2 с пока ждём реванша. Если на сервере давно ничего не
меняется, интервалы растягиваются ещё вдвое. Комната живёт три часа с
последнего обращения; соперник считается отключившимся после 25 секунд тишины, и
об этом говорит пилюля внизу экрана — она появляется только когда что-то не так
(там же видно, если пропала связь с сервером).

Сервер знает только ходы, случайные токены и имя, которым игрок представился
сам — ни аккаунтов, ни регистрации, ни истории партий. Имя необязательно:
без него соперник так и зовётся «Соперник».

## Тесты

Все прогоняют ту же логику, что работает в бою.

```bash
node tools/test-rooms.mjs     # комнаты, очерёдность, реванш, ошибки — без браузера
node tools/dev-server.mjs &   # локальный сервер на 8787 с хранилищем в памяти
node tools/run-all.mjs        # двадцать две проверки подряд
```

Для игровых тестов нужен Playwright: `npm i -g playwright`. Каждый из них
(`tools/test-<игра>.mjs`) открывает два окна браузера и играет настоящую партию:
создание комнаты, вход по коду, блокировка чужого хода, синхронизация ходов,
итог, фант, реванш, обрыв связи.

Отдельно стоят два теста, которые проверяют не игру, а связь:

* `tools/test-race.mjs` — ход и опрос соперника уходят одновременно сорок раз
  подряд. Ни один ход не имеет права пропасть.
* `tools/test-lost.mjs` — связь рвётся посреди партии: сначала наглухо, потом
  теряется каждый третий запрос у обоих игроков. Поле должно сойтись.
* `tools/test-soak.mjs` — долгая партия в «Мемо-дуэли», «Захлопни ящик»,
  «Доббле» и «Взломщике» на телефонной связи: часть запросов не доходит, часть доходит, а ответ теряется,
  часть застревает и доезжает, когда игрок успел сходить ещё раз, а часть повисает
  совсем — ни ответа, ни ошибки (такой запрос `net.js` обрывает через 8 секунд). Один раз за
  партию соперник на девять секунд пропадает из сети совсем. Проверяется не
  правило игры, а покой: **когда никто не нажимает, поле обязано стоять на
  месте** и быть у обоих одинаковым. `SEED=` меняет расклад помех.

Ещё одна проверка — не про игру и не про связь, а про то, как приложение выглядит:

* `tools/test-layout.mjs` — меню игр на низком экране (iPhone SE в Safari — 375×548),
  колонка на планшете и компьютере, телефон боком, тени спрятанных шторок и режим
  «Уменьшить движение». Всё, что нашла проверка перед релизом 28.09.2026.

**Хранилище в тестах отвечает с задержкой** (`tools/memstore.mjs`, `LAG=` у
локального сервера). Без неё сетевые гонки не воспроизводятся вообще — а именно
они и ломают игру в бою.
