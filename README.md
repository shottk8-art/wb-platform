# Панель продавца Wildberries

Веб-платформа для продавцов WB: загружаете отчёты — получаете дашборд с прибылью
по артикулам. Каждый пользователь видит только свои данные, но может поделиться
публичной read-only ссылкой на витрину своего магазина.

Стек: **статический фронтенд (HTML/CSS/JS) + Supabase (база данных + авторизация
+ Edge Function) + Netlify (хостинг) + GitHub (репозиторий и авто-деплой)**.
Без сборки, без своего бэкенд-сервера — вся логика на клиенте и в одной
Edge Function, безопасность обеспечивают политики RLS в Supabase.

## Как это устроено

- **Авторизация** — вход через Telegram (виджет Telegram Login), без паролей
  и без email. Кнопка входа проверяется Edge-функцией `telegram-auth`
  (`supabase/functions/telegram-auth`): она сверяет подпись данных от
  Telegram секретным токеном бота, затем через Admin API создаёт/находит
  пользователя Supabase (email вида `tg<id>@telegram.wbplatform.local`,
  реальный email не используется) и отдаёт фронтенду одноразовый токен,
  который тот сразу меняет на сессию (`auth.verifyOtp`). Письма никуда
  не уходят.
- **Данные** — при первом входе пользователю создаётся магазин (`shops`). Все
  остальные таблицы (`monthly_reports`, `sku_sales`, `sku_costs`) привязаны к
  `shop_id`.
- **Загрузка отчётов** — файлы .xlsx разбираются прямо в браузере (библиотека
  SheetJS), на сервер уходят только посчитанные числа, а не сами файлы.
- **Публичная витрина** — `/s/<slug>` открывает тот же дашборд в режиме только
  чтения, без входа в аккаунт. Доступ регулируется переключателем в кабинете
  и политикой RLS `share_enabled = true`.

## Шаги для запуска (на завтра)

### 1. Supabase

1. Зайдите на [supabase.com](https://supabase.com) → New project.
2. Откройте **SQL Editor → New query**, вставьте содержимое файла
   `supabase/schema.sql` целиком и нажмите Run.
3. **Authentication → URL Configuration** — впишите адрес сайта (Netlify) в
   поля Site URL и Redirect URLs, например `https://ваш-сайт.netlify.app/**`
   (можно и через `supabase/config.toml` + `supabase config push`).
4. **Project Settings → API** — скопируйте `Project URL` и `anon public`/
   `publishable` key.
5. **Edge Function `telegram-auth`**:
   - создайте бота через [@BotFather](https://t.me/BotFather) (`/newbot`),
     сохраните токен;
   - `supabase secrets set TELEGRAM_BOT_TOKEN="<токен>"`;
   - `supabase functions deploy telegram-auth --no-verify-jwt`;
   - в @BotFather выполните `/setdomain` для вашего бота и укажите домен
     сайта (например `wb-platform.netlify.app`) — без этого шага виджет
     Telegram Login на сайте покажет ошибку «Bot domain invalid».

### 2. Фронтенд

1. Скопируйте `assets/config.example.js` в `assets/config.js`.
2. Впишите туда `SUPABASE_URL` и `SUPABASE_ANON_KEY` из шага 1.5.
   (Этот ключ безопасно коммитить в публичный репозиторий — он не даёт прямого
   доступа к данным, всё разграничение — на уровне RLS-политик в базе.)

### 3. GitHub

```bash
cd wb-platform
git init
git add .
git commit -m "Панель продавца WB: первая версия"
git branch -M main
git remote add origin https://github.com/<ваш-аккаунт>/<репозиторий>.git
git push -u origin main
```

### 4. Netlify

1. [app.netlify.com](https://app.netlify.com) → Add new site → Import an
   existing project → выберите репозиторий на GitHub.
2. Настройки сборки уже заданы в `netlify.toml` (публикуется корень репозитория,
   сборка не требуется) — просто нажмите Deploy.
3. После первого деплоя скопируйте адрес сайта (`https://....netlify.app`) и
   вернитесь в Supabase (шаг 1.4), чтобы дописать точный адрес в Redirect URLs.

### 5. Проверка

1. Откройте сайт → нажмите кнопку Telegram Login → подтвердите вход в Telegram.
2. В личном кабинете перетащите файл «Сводного отчёта по продавцу» — должны
   подхватиться все месяцы, которые есть в файле.
3. Загрузите отчёт «Продажи» за нужный месяц (год/месяц указывается перед
   загрузкой файла).
4. Заполните себестоимость по артикулам и расход на рекламу — прибыль
   пересчитается автоматически.
5. Скопируйте ссылку на витрину (блок «Публичная витрина») и откройте её в
   режиме инкогнито — данные должны быть видны без входа в аккаунт.

## Структура репозитория

```
wb-platform/
├── index.html          landing + вход через Telegram + публичная витрина (?shop=slug)
├── app.html             личный кабинет: загрузка отчётов, ручной ввод, дашборд
├── netlify.toml         конфиг деплоя + редирект /s/:slug
├── assets/
│   ├── styles.css        дизайн-система (светлая/тёмная тема)
│   ├── config.example.js  шаблон конфига — скопировать в config.js
│   ├── supabaseClient.js  инициализация клиента Supabase
│   ├── auth.js            вход через Telegram, создание/переключение магазинов
│   ├── parse.js           разбор XLSX-отчётов WB (SheetJS) прямо в браузере
│   ├── upload.js          запись разобранных данных в Supabase
│   └── dashboard.js       загрузка данных периода, расчёты, отрисовка графиков
└── supabase/
    └── functions/telegram-auth/  Edge Function: проверка Telegram-подписи → сессия Supabase
    └── schema.sql         таблицы + политики RLS — выполнить в Supabase один раз
```

## Что можно доделать дальше

- Импорт исторических периодов из уже заполненного Excel-дашборда (если он
  использовался раньше).
- Уведомления на почту о новых загрузках / автоматическое сравнение с прошлым
  месяцем.
- Роли доступа внутри одного магазина (например, бухгалтер с правом только
  на ручной ввод).

## Статистика промокодов TOPLASH

Отдельная страница `/promocodes.html` использует существующий вход через Telegram.
Владелец TOPLASH открывает её из меню магазина. В «Названия промо и доступ» он
может добавить в список UUID из карточки промокода WB, его название и сам код,
а также выдать доступ по нику Telegram. В ответ статистики входят только ID
из этого сохранённого списка: фильтрация выполняется на сервере. Одинаковые
названия/коды у разных ID не объединяются. Промокоды без операций видны с нулём
только при полном покрытии финансового периода; пустой список требует настройки
и не открывает все исторические ID. Начальный список считан из карточек кабинета
WB; внутренний `data-row-key` строки не является финансовым ID промокода.
Приглашённый человек входит по той же отдельной ссылке; доступ активируется
только по имени из проверенного Telegram-пакета. Приглашение не добавляет его
в `shop_members` и не открывает остальные данные магазина. Изменять названия,
выдавать доступ и запускать загрузку WB может только владелец.

Источник — официальный финансовый API WB: `uuidPromocode`, `quantity`,
`retailPriceWithDisc`, `sellerOperName`, `docTypeName`, `rrDate`.
`sellerPromoId` не используется как ID промокода. Названия финансовый API не
возвращает: названия и коды сохраняются в справочник отдельно. Новые ID добавляет
владелец. Считаются **выкупленные
товары**, а не все оформленные заказы или количество уникальных заказов.
Сумма выкупов — количество × цена продавца с согласованной скидкой; возвраты
показаны отдельно, итог равен выкупам за вычетом возвратов. Отбор дат идёт по
`rrDate`, то есть дате операции финансового отчёта, в пределах последних
12 календарных месяцев. Данные текущего дня могут появиться позже у WB.

Обычная финансовая загрузка TOPLASH сохраняет агрегаты по промокодам в том же
проходе. Для старого периода, загруженного без ID, владелец запускает отдельную
компактную догрузку. Она выполняется на сервере, использует общий лимит
финансового API и уступает основным финансовым заданиям. Хранятся только дневные
суммы/количества по ID, без исходных заказов и персональных данных; сохраняются
два последних полных снимка догрузки за месяц. Отсутствующее поле ID или неполное
покрытие не считается нулём. При обновлении сохраняется последний полный результат.
Чтение статистики, поиск, сортировка и наведение не обращаются к WB.

Проверки: `node tests/wb-promocodes.mjs`, `node tests/promocodes-routes.mjs`,
`node tests/promocodes-ui.cjs`; транзакционные проверки миграции —
`tests/wb-promocodes.sql`. Нужны миграции `promocode_statistics` и
`promo_catalog_scope` перед публикацией обновлённых `wb-api` и `telegram-auth`.
Реальные названия, коды и ID импортируются отдельно и не включаются в миграции,
тестовые примеры или опубликованные исходники.
